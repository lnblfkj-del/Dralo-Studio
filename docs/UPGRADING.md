# 单机源码升级

本说明针对本仓库的公开单机 SQLite 迁移基线 `ds_0001`。不适用于此前内部数据库、官网云端 PostgreSQL 或其他项目的数据库；初始化拒绝旧库时不要删除数据或强行改迁移编号。

## 升级前

1. 保存工作，检查任务中心；存在执行中或请求结果未定的任务时先停止发布，核对渠道是否已返回、是否可能计费。
2. 停止本部署的 API 和 Worker，避免数据库与素材在备份期间继续变化。
3. 完整备份 `.env`、数据库文件、素材目录及存储配置。SQLite 若存在 `-wal` / `-shm` 文件也要妥善处理；不要只在服务运行时复制一个主数据库文件。
4. 记录当前源码提交和依赖版本，保留完整备份。模型配置加密密钥不可丢失或重新生成，否则已有密钥可能无法解密。

## 更新与启动

先阅读 [更新记录](../CHANGELOG.md)，获取经发布的源码版本，不覆盖 `.env`、数据库、素材或个人自定义 Skill。按 [快速开始](QUICKSTART.md) 更新锁定依赖并重新构建前端和导演台。

在激活 Python 环境后执行：

```sh
cd apps/server
python -m app.standalone_initialize
```

工具会接纳匹配的公开单机基线并保留现有数据；不自动采用未知数据库。升级涉及其他迁移版本时，以该版本发布说明为准，不自行修改迁移文件或直接降低数据库版本。

分别启动同一套源码下的 API 与 Worker：

```sh
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

```sh
python -m app.jobs.worker
```

重新打开浏览器，先检查登录、旧项目、素材预览、模型配置与任务状态。不要为了验证更新而重复点击收费生成。

## 片段规划与费用

新版整集规划与片段脚本使用版本化响应协议。旧任务保留原有冻结协议、模型及预算，不会因升级改成新格式。API、Worker、前端必须匹配，不能只更新其中一部分。

在当前规划弹窗重试时先尝试使用保存响应恢复；需要重新调用文本模型时会明确提示范围和可能再次收费。成功片段与历次响应保留，取消收费确认不提交新的模型请求。超时且结果未定时，上次请求也可能已计费。

推荐配置与适用范围见 [模型配置说明](DIRECTOR_MODEL_CONFIGURATION.md)。推荐不自动替换你的模型，也不保证所有同名代理渠道都支持原生结构化格式。

原创与完整导入正文走同一规划链路；导入大纲应先确认大纲、完成正文并确认。连续故事的前集不完整或未确认时，不能跳到后集规划。明确旁白原文会保留，未知人物及缺失台词不猜测补齐。系统不能自动证明上传剧本在叙事上完整。

## 出现问题

停止新生成，不反复付费重试。记录源码版本、任务编号、错误码与无敏感信息的失败详情；不要在 Issue 中上传 `.env`、密钥、客户原文或完整响应。

仅切回旧代码不等于恢复数据库和素材。必要时先保留升级后新增数据，再按照匹配备份恢复；不能覆盖新项目或把后续写入静默丢弃。
