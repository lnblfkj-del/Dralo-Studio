# R3 单机源码切换说明

R3 使用新 SQLite 基线 `ds_r3_0001`，不提供旧业务项目、任务或片段计划转换。单机初始化及隔离重置已通过实际候选运行验收；官方云端已归档旧测试库并切换新流程。云端状态不等于你的本机已经升级，也不代表所有收费渠道均已验收。只使用明确标注 R3 的源码版本，不要直接覆盖旧部署。

## 新安装

使用独立目录、独立数据库、独立素材和日志目录，按 [快速开始](QUICKSTART.md) 初始化。不要连接旧业务库或启动旧 Worker。前端、API 与 Worker 必须来自同一版本。

初始化只接纳空库或匹配的新基线。旧 `ds_0001`、内部数据库或未知数据库会被拒绝，不会静默删除或更改；禁止手工改迁移编号。

## 旧测试部署

保留原部署，不自行删库。后续切换必须先停止 API、调度和 Worker，核对已发出的上游请求，完整备份配置、数据库及素材，并隔离旧结果目录。

在新候选的 `apps/server` 中先只读检查；路径示例须替换为自己的旧部署 `.env` 和全新私有目录：

```sh
python -m app.standalone_reset --source-env D:/Dralo-old/.env --output D:/Dralo-private/r3-reset
```

默认只读，不创建目录或改原库。准备新库需明确确认停服及清除测试项目：

```sh
python -m app.standalone_reset --source-env D:/Dralo-old/.env --output D:/Dralo-private/r3-reset --apply --confirm-reset-test-projects --services-stopped
```

若有非终态任务，先与渠道核对已经发出的请求和费用；核对后才能追加 `--acknowledge-inflight`。工具不会取消上游请求、撤销费用或重新调用模型。`--services-stopped` 是操作者的停服确认，不是自动停服命令；近期 Worker 心跳会阻止准备。

新库保留账号、权限、工作空间成员、渠道密文、价格、执行配置和自定义 Skill，旧业务表为空。旧内置 Skill 由新版重新安装；旧音频/视频已验证状态、旧会话及旧任务不继承。模型配置加密密钥保持不变，登录密钥和执行命名空间重新生成，账号需要重新登录。

完整旧数据库及旧 `.env` 保存在 `archive`，账本和未定费用供核对，不导入新库，避免旧任务 ID 误关联。旧素材目录原样保留，不被复制进新业务目录，也不会被清空。对象存储凭据仅归档；先配置新对象前缀、核验后再启用同步，不复用旧同步游标。

工具只支持已识别的公开单机基线，不支持云端 PostgreSQL。它生成 `fresh.sqlite3`、`deployment.env`、独立素材/日志目录和 `reset-report.json`，**不会激活新库或替换任何现有 `.env`**。失败的半成品不得启用，使用新的输出目录重新准备，不绕过校验。

新素材目录由初始化入口安装校验内置风格图片。首次启动会补齐未修改的内置风格图片引用；自定义风格的内容不会被覆盖。旧用户素材只归档、不导入，因此自定义风格的旧参考图需要在新库中重新选择，不能沿用旧媒体编号。

## 激活准备好的新库

以下步骤只适用于准备成功且 `reset-report.json` 无错误的新重置包。先确认旧 API/Worker 已停止，旧配置、数据库和素材归档完整；不要仅关闭网页。保留准备包在原位置，其数据库和目录使用绝对路径，不能移动后直接启动。

1. 在独立目录取得同一 R3 源码版本，按快速开始安装依赖并构建前端；不要在该目录运行 `init_local_config.py` 重新生成加密密钥。
2. 将准备包中的 `deployment.env` **复制**到新源码根目录，文件名为 `.env`。目标必须尚不存在；不要覆盖旧部署 `.env`。这一步才激活新库配置，准备工具本身不会激活。配置包含私密信息，不提交 Git、不放在网站静态目录中。
3. 在新源码的 `apps/server` 中执行 `python -m app.standalone_initialize`，确认新基线及内置图片校验成功。失败则停止，不启动 Worker，不改迁移编号。
4. 按快速开始分别启动新 API 与新 Worker。两个进程必须从同一源码目录读取同一 `.env`；不要启动旧 Worker。先登录并新建一个测试项目，确认素材、模型配置及生成入口正常，再开始新的收费调用。
5. 在模型管理中重新登记并核验音频协议、音色、视频模式和规格。旧的“已验证”状态不继承；未核验模型被拒绝用于规划是保护措施，不要把它直接改为“已验证”。

激活失败时暂停新 API/Worker，并保留新库及日志供排查，不覆盖旧归档，不恢复旧片段规划分支。已有结果或费用未定时先按渠道任务编号核对；不得通过反复生成来修复数据库问题。

不要清空共享存储根目录，也不要重新生成现有模型配置加密密钥。对于结果未定的请求，停止本机任务不等于取消上游生成或费用。

## 新流程的重试与费用

新系统使用冻结计划和保存响应。保存失败应优先在当前页面恢复，不再次调用模型；确实需要新模型调用时，界面会说明范围与可能再次收费。切换视频模型本身不自动生成视频，不兼容的片段需要重新规划。

原创与完整导入正文走同一规划链路；不完整的故事材料应先完成并确认正文。未知人物、缺失对白或不明确的说话人不能靠省略来通过校验。

音频、订阅权限及模型能力需要核验，不能把旧配置中的手工“已验证”标记当成真实账户证明。FFmpeg/FFprobe 配置见 [快速开始](QUICKSTART.md)，模型要求见 [模型配置说明](DIRECTOR_MODEL_CONFIGURATION.md)。

## 出现问题

暂停新生成，记录版本、任务编号和无敏感信息的失败详情；不要在 Issue 中上传 `.env`、密钥、客户原文或完整响应。不要反复点击收费生成。

仅切回旧代码不等于恢复旧数据库与素材。R3 不退回旧规划分支，发布失败时应暂停新提交并修复新系统；实际切换与恢复步骤以完成验收后的发布说明为准。
