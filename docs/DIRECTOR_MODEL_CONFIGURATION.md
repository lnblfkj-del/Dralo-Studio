# 整集规划与片段脚本模型配置

本页适用于包含版本化导演响应协议和结构化输出适配器的版本。更新前后端及 Worker 后再启用新参数，不把此配置提前填入旧版本。

## 模式选择

| 模式 | 用途 | 注意事项 |
| --- | --- | --- |
| `text` | 默认兼容模式、自定义或尚未验收的渠道 | 仍按响应协议解析和校验；不发送原生格式参数 |
| `json_object` | 已验证 JSON 模式的渠道 | JSON 有效不等于字段、镜头、台词或时长正确 |
| `json_schema` | 已验证完整导演 Schema 的渠道 | 优先约束结构；仍需本地业务校验 |

模式默认保持 `text`，不会擅自替换已选择模型，也不会因参数不支持而悄悄切回另一模式或付费换模型。结构化模式绑定实际渠道编号、模型标识、接口协议和地址；地址或模型改变后需要重新验收。

支持的适配协议：OpenAI 兼容 / NewAPI 的 JSON 与 JSON Schema；Anthropic Messages 的 JSON Schema；Google Gemini 原生的 JSON 与 JSON Schema。这里描述的是系统参数适配能力，不代表任意代理渠道已经验收。

## 设置方法

在文本模型编辑弹窗展开“默认参数与费用配置”，编辑“默认参数（JSON）”。保留已有参数，不用以下示例覆盖整份配置。预算和超时另在同一弹窗的“文本输出与超时”中设置，以对应表单值为准。

普通模式：

```json
{
  "_structured_output": { "mode": "text" }
}
```

以下是 OpenAI 兼容渠道的结构化配置示例，不是可直接使用的真实渠道信息：

```json
{
  "_structured_output": {
    "mode": "json_schema",
    "route": {
      "provider_id": 123,
      "model_id": "your-configured-model-id",
      "protocol": "openai_compatible",
      "base_url": "https://your-provider.example/v1"
    }
  }
}
```

- `provider_id` 是本部署的渠道编号，不是模型编号；`model_id` 是请求标识，不是界面显示名称。不要复制其他部署的编号。
- `base_url` 必须与系统规范化后的实际执行地址完全一致；相同品牌的不同代理地址不共用验收结论。
- JSON 模式将 `mode` 改为 `json_object`，不要另外手填 `response_format` 或完整导演 Schema。适配器会按任务阶段生成请求。
- 可选 `evidence_sha256` 保存渠道验收记录摘要，但它只是记录引用，不是平台认证，也不能代替真实验收。
- 早期小样本使用过 16384 tokens / 300 秒；当前候选复验使用明确的 16384 tokens 输出预算、600 秒总超时和最多并发 2。须按实际渠道支持范围和任务规模设置，不是所有模型的通用值。推理 Token 可能占用输出预算，不能只看可见文字长度。
- 结构化模式必须有明确输出预算；预算可以用模型弹窗的“默认输出预算”或“单次最大输出预算”配置。未设置时会在提交前提示，不自动套用一个可能超出渠道限制的数值。
- 首响应和流式空闲超时沿用已有文本执行设置。不要只增加并发或延长所有超时来掩盖渠道错误。
- 结构化格式配置不改写现有超时。模型单独配置的总超时优先于渠道连接超时；没有模型配置时才沿用渠道值，不能用连接测试的等待时间代替规划任务的执行设置。

## 验收与升级

### 已验收候选配置

2026-10-09 的本地验收推荐当前实际配置的 `gpt-6-sol` 路由作为整集规划与片段脚本的默认候选：OpenAI 兼容接口、`json_schema`、明确 16384 tokens 输出预算、600 秒总超时、最多并发 2。推荐不自动更改你的设置；渠道编号与地址必须使用本部署实际配置，不能照抄其他部署。这个预算和超时只作为已测起点，不是任意任务或模型的保证值。

依据为有效自编百段首次 100/100、完整业务装配，以及真实剧本两处节选四段、合法变化、动物身份、实际边界到片段串联和扩展/密集/静默补验。媒体是合成元数据，范围不是全剧、所有语义或实际图像/口型认证；密集对白仍可能需要调整视频时长与边界，不能删词过关。

只签收了该实际渠道和配置，不是“全球 bug 最少”排名，也不认证所有同名代理。DeepSeek 当前规则尚未完整补验且曾遇额度不足，不作为已验收备用；其他渠道、不同模型/地址或不同视频能力需自行验收，不自动切换、降级或再次付费。云端路由及新/旧部署仍须完成部署前后复测，不能直接用本地成绩替代。

先在隔离项目中核对完整导演请求，而非只测试连接或让模型返回一个简单 JSON。至少确认字段限制实际生效、正常结束状态可核对、真实模型/请求标识和用量可记录，并验证当前视频模型的时长、镜头数与参考能力。

原生 Schema 使用同源响应类型生成，展开本地类型引用。部分长度、数值和数组限制以说明形式传递，仍由本地类型和业务合同强制校验。因此“开启结构化输出”不能保证正文、因果或时长运算永不出错。

已创建任务冻结本次路由、输出模式、格式及执行预算；修改设置不改变在途任务。旧任务按原冻结格式处理，不自动升级协议。API、Worker 和前端应部署相匹配的版本。

新版协议的 AI 进入/结束状态标记为建议。相邻描述措辞不同会提示核对，不单凭文字不完全相同认定为物理冲突；旧的明确状态保护保持。提示不等于已经验证状态正确，确认草稿前仍需核对人物站位、道具归属与动作接点。

新生成提示明确区分动作前的进入状态与动作后的结束状态。在可核对的同场来源中，站位、持物、接触与服饰延续至原文明示改变；说话、观察或换景别不能自行变成松手、拿取或移动。原文明示交接、松手、起身或转场时照常保留。未知细节不能填成互斥备选，负向提示不能禁止原文已有对白与声音。这些是生成约束，不是自动物理连续性证明；只读邻接节选也不能当作相邻已生成结果。

单片段提示列出当前镜头与冻结正文行的对应关系，锁定镜头仍不改写。正文明确发生的动作需要在对应镜头中呈现，不能只出现在结束状态，或因为下一段描述结果而提前当成开场事实；这份只读映射不替代动作内容审阅。

新创建的整集规划任务冻结姿态来源检查版本。系统仅提取同场原文中可唯一对应角色的明确站、坐、蹲、躺及起身/坐下等措辞，保留行号和原句；在主体、动作、进入/结束状态中发现可确定的反向姿态时拒绝装配。主体优先描述身份与构图，动作和状态描述姿态起止，避免同一响应互相矛盾。

该检查不猜测代词、歧义别名、复杂未识别动作、条件、否定或对白中的姿态；不使用未来正文确认当前状态。合法姿态转换和跨场保留，含锁定镜头的场景不做这层自动姿态核验，以免覆盖已确认的人工编辑。未被拦截不等于已自动证明语义正确。旧任务继续按原冻结规则恢复，不追加强制检查。

正文中的已知角色名可单独一行，以冒号结束，下一行是完整带引号台词。系统保留角色名、换行与原句；缺少台词、引号未闭合或身份不明时不会猜测补齐。此支持不代表任意剧本文档格式都已验收。

## 失败与费用

在当前规划弹窗使用“重试未完成片段”。服务端先检查有效保存响应能否免费恢复，再明确列出需重新调用的范围；需要模型调用时由用户确认费用。已成功片段保留，不因为一个失败片段重新生成整集。

系统只处理可证明等价的表示差异并留下转换记录，例如归属一致的折行重复登记、原生模式中完全相同的重复对象或镜头。冲突内容、空镜头、来源变化、截断和时长超限不能通过删除字段、补空值或选取其中一版来假装成功。

姿态来源冲突同样保留原响应和已成功片段，不静默替换词语或重新调用模型。先在当前规划弹窗走免费恢复；仍不成立而需要新文本调用时，继续使用现有明确范围与费用确认流程，不自动收费重试。

渠道安全拦截、鉴权或额度问题应先处理原因；不能把安全拦截当参数错误或可以免费修复的脚本。请求超时且无法确认渠道结果时，上次可能已计费，重新调用也可能再次计费。没有价格配置或渠道结算数据时，系统不能承诺具体金额或显示为免费。

该设置只控制新版整集规划与片段子任务的原生输出格式，不代表故事策划、大纲、资产提示词等其他工作流也已切换到同一原生 Schema。
